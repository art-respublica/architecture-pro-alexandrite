#### Анализ компании в контексте планирования кеширования

MES API является самым нагруженным сервисом компании, он отвечает за расчет стоимости по заказу, принимает заказы от других поставщиков, обслуживает операторов. 
Для повышения его производительности предлагается в первую очередь добавить кеширование на частотные операции, такие как получение справочной информации (списка номенклатуры, их цен, остатков на складах, спецификации для производства).

По результатам внедрения кеширования на MES API будет расмотрен вопрос внедрения кеширования на других сервисах.


#### Мотивация
Что даст компании кеширование в сервисе MES?
1. Увеличение производительности сервиса
    а) MES выполняет тяжёлые расчёты для одинаковых спецификаций многократно. Кеширование уберет задержки в производственном цикле, снизит нагрузку на CPU.
    б) Все вызовы по API со стороны других продавцов синхронные. Кеширование часто запрашиваемых справочников (товаров, цен, остатков на складах, спецификации) значительно сократить время обработки запросов для партнеров.
2. Снижение нагрузки на базу данных.
3. Уменьшение времени ответа на запросы по API.
4. Уменьшение среднего времени расчета для заказов.
5. Косвенно, экономию на ресурсах из-за отсутсвия необходимости масштабировать оборудование.


#### Предлагаемое решение
Планируется включить в кеширование следующие сущности MES API:

|          **Сущность**           | **Тип кеша**   | **Паттерн кеширования** | **TTL, мин** | **Обоснование**                                                                              |
|:-------------------------------:|:---------------|:------------------------|:-------------|:---------------------------------------------------------------------------------------------|
|           Номеклатура           | Redis, сервер  | Cache-Aside             | 15-60        | Изменяется редко, запросов очень много из разных сервисов                                    |
|        Цены номенклатуры        | Redis, сервер  | Write-Through           | 5-15         | Критичны для расчета и принятия решения, меняются не часто, запрашиваются из разных сервисов |
|      Остатки номенклатуры       | Redis, сервер  | Write-Through           | 1-5          | Критичны для расчета и принятия решения, меняются часто, запрашиваются из разных сервисов    |
|  Спецификации для производств   | RAM, сервер    | Cache-Aside             | 60-300       | Изменяется редко, запросов очень много, используются только в MES API                        |
| Результаты расчета спецификацй  | Redis, сервер  | Cache-Aside             | 5-15         | После записи почти не пересчитываются, запрашиваются из сервисов и по API                    |
| Статус доступности оборудования | RAM, сервер    | Write-Through           | 1-2          | Критично для расчета                                                                         |
|    Очередь заказов на расчет    | RAM, сервер    | Write-Through           | 1-2          | Меняется очень часто                                                                         |

Инвалидация кеша будет происходит по времени жизни и по идентификатору сущности.
